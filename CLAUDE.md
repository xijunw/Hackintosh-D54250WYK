# Hackintosh D54250WYK — CLAUDE.md

## Repository Overview

This repository documents a personal Hackintosh configuration for the **Intel NUC Kit D54250WYKH** running macOS via the **OpenCore EFI bootloader**. It is a reference/study repository — no pre-packaged EFI is distributed. Changes here update documentation, ACPI source files (`.dsl`), compiled ACPI binaries (`.aml`), and OpenCore `config.plist` files.

**No executable code, build system, or test suite exists.** "Development" means editing ACPI DSL, plist configuration, or documentation files.

## Active OpenCore Configuration

### OpenCore Version
OpenCore 1.0.1 (files validated with `ocvalidate`). Follow the [Dortania Haswell guide](https://dortania.github.io/OpenCore-Install-Guide/config.plist/haswell.html) for quirks.

### Two Config Variants
| File | Purpose | Key differences |
|------|---------|-----------------|
| `config.v101.picker.plist` | Daily driver | ShowPicker=true, Timeout=5s, debug off, all kexts on |
| `config.v101.emergency.plist` | Debug / USB install | Verbose `-v`, HideAuxiliary=false, Wi-Fi/BTLE kexts disabled, SecureBootModel=Disabled, ScanPolicy=0 |

Both files live in `Actively Used/` and require a **personalised SMBIOS** — never commit real MLB/SystemSerialNumber/SystemUUID/ROM values. Replace placeholders using [GenSMBIOS](https://github.com/corpnewt/GenSMBIOS).

### Critical OpenCore Quirks (Kernel section)
- `AppleXcpmCfgLock = true` — MSR `0xE2` is locked and cannot be unlocked on this NUC
- `AppleCpuPmCfgLock` is **not** needed (only affects pre-El Capitan/IvyBridge paths)
- `IgnoreInvalidFlexRatio = true` (UEFI quirk) — required for Monterey to boot

### Intel HD Graphics 5000 Injection (DeviceProperties)
```xml
<key>AAPL,ig-platform-id</key>
<data>BgAmCg==</data>          <!-- 0x0A260006 byte-swapped -->
<key>device-id</key>
<data>JgoAAA==</data>           <!-- 0x0A260000 byte-swapped -->
```
Do **not** use the old `0x0D220003` platform ID — it causes acceleration issues on recent macOS + WhateverGreen versions.

### Required Kexts (load order matters for BTLE)
1. Lilu.kext
2. VirtualSMC.kext + SMCProcessor.kext + SMCSuperIO.kext
3. WhateverGreen.kext
4. AppleALC.kext (layout-id `0x01`)
5. IntelMausi.kext
6. AirportBrcmFixup.kext (compatible ID `pci14e4,43a0`)
7. **BlueToolFixup.kext → BrcmFirmwareData.kext → BrcmPatchRAM3.kext** (order is mandatory)
8. USBPorts.kext (generated by Hackintool)

## Active SSDTs (`SSDTs/`)

Each SSDT exists in both human-readable `.dsl` (ACPI source) and compiled `.aml` (binary) form. The `.aml` is what OpenCore loads; the `.dsl` is the canonical source for edits.

| SSDT | Purpose |
|------|---------|
| `SSDT-EC-USBX` | Adds fake `EC` device (required by macOS) + `USBX` with Macmini7,1 USB power values |
| `SSDT-EHCI-OFF` | Disables EHCI controller (variables `EH1D`/`EH2D`); routes all USB through XHCI |
| `SSDT-NAMES` | Adds `MCHC` (mandatory for recent macOS) + `IMEI` + `BUS0`/`DVL0` under SMBus |
| `SSDT-PLUG` | Injects `plugin-type=1` on first CPU core to activate XCPM (X86PlatformPlugin) |
| `SSDT-XOSI` | Emulates Windows `_OSI` string for broader compatibility (currently **disabled** in plist) |

### Editing SSDTs
1. Edit the `.dsl` source file.
2. Compile with `iasl` (from [acpica-tools](https://github.com/acpica/acpica) or included in OpenCore utilities): `iasl SSDT-NAME.dsl` → produces `SSDT-NAME.aml`.
3. Commit both `.dsl` and `.aml` together.
4. Keep `DefinitionBlock` header fields consistent: `TableSignature="SSDT"`, `ComplianceRevision=2` (64-bit arithmetic), `OEMID="OC"`.

## USB Port Mapping

The generated `USBPorts.kext` defines exactly these ports with `UsbConnector=3` (USB 3.0 physical connector):

| USB 2.0 | USB 3.0 | Location |
|---------|---------|----------|
| HS01 | SS01 | Front RIGHT |
| HS02 | SS02 | Front LEFT |
| HS03 | SS03 | Rear BOTTOM |
| HS04 | SS04 | Rear TOP |
| HS07 | — | Internal BTLE |

Internal USB 2.0 headers (HS05, HS06, HP11–HP18) and Consumer IR are **disabled in BIOS** and absent from the kext. EHCI controller (and its hub ports) is disabled via `SSDT-EHCI-OFF.aml`.

## Sleep/Wake

Apply once after macOS installation via Terminal:
```bash
sudo pmset autopoweroff 0
sudo pmset powernap 0
sudo pmset standby 0
sudo pmset proximitywake 0
sudo pmset tcpkeepalive 0
```
Do **not** enable "Wake for Ethernet Network access" in System Preferences if Wake on LAN is disabled in BIOS.

## SMBIOS & iServices

- Target model: `MacMini7,1`
- `ProcessorType`: `1541` (integer) → `CPU_MODEL_HASWELL (0x0605)`
- Use [GenSMBIOS](https://github.com/corpnewt/GenSMBIOS) to generate MLB, SystemSerialNumber, SystemUUID
- ROM: take the 12-hex-digit MAC of `en0` (no colons) → convert to Base64 for the `<data>` value
- Verify ROM persistence: `nvram -x 4D1EDE05-38C7-4A6A-9CC6-4BCCA8B38C14:ROM`

## Conventions for AI Assistants

- **No build system** — there are no `make`, `npm`, or `python` commands to run.
- **Compiled binaries** — `.aml` files are binary ACPI tables. Always update the corresponding `.dsl` source and recompile; never edit `.aml` files directly.
- **Plist files** — OpenCore config plists are standard Apple XML plists. Use a plist editor or `plutil` for validation. Do not commit real SMBIOS identifiers.
- **Sensitive data** — MLB, SystemSerialNumber, SystemUUID, and ROM values are personal. If editing plist files, leave these as clearly marked placeholders (e.g., `XXXXXXXXXXXX`).
- **Documentation-first repo** — most changes are to Markdown documentation or ACPI source. Prefer clear, factual prose matching the existing style (no emoji unless already present in that document).
- **File naming** — existing files follow `SSDT-NAME.{dsl,aml}` for SSDTs and `config.vVER.variant.plist` for OpenCore configs. Match this pattern for any new files.
- **Branch** — active development happens on `claude/claude-md-docs-6Fw1Z`; stable content is on `master`.
